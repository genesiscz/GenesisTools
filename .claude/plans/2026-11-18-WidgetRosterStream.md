# Widget roster publication

The widget worker owns one revision at a time. Freeze the seven-day index membership and its mtime order using small file descriptors. Hydrate exact paths through the existing session-row readers, newest first. The cursor is a position in that fixed revision. It advances by input paths even when a session disappears. Publish the first page immediately and increase the page size for older rows. Do not keep a history of pages. A change during a run queues a successor.

Stream agent parents from the existing tree builder after its shared reads. The final tree uses the existing open/live order, parent limit, orphan assignment and prompt previews. Keep a completed warm roster visible during refresh. Exact updates to listed parents refresh those rows and trees. Reconcile membership, live processes, journals and otherwise unplaceable changes with a full safety read.

The existing watch channel publishes snapshots. Its atomic cache file holds the latest contiguous prefix and its progress. A reader opens one file to join at any time. Settings and Hub read recent publications after a writer exits, subject to the same age checks. A new watch may seed from the longer startup window. A complete old-format file is a valid seed. Avoid serializing unseen intermediate revisions faster than readers can consume them.

The orchestrator measures at load below ten and at high load, recording per-step process CPU and elapsed time, first-page latency, and live watch RSS over thirty minutes. It runs the widget tests, builds the native app and observes fifteen minutes of ordinary use. The existing incident numbers cover pipe traffic and whole-worker CPU only.
